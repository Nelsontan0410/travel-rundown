# 手机版导航与日程卡片（2026-10-21）

## 范围与隔离

本次用户明确授权新增手机版长按交互与底部导航。所有视觉覆盖放在 `@media (max-width: 768px)`；交互判断使用完全一致的 `matchMedia('(max-width: 768px)')`。769px 以上使用原导航、原顶部面板、原复选框和原导航文字。新导航内部组件仅在手机断点挂载，桌面无新增导航数据订阅。

`MobileHoldCard` 复用原卡片 DOM 层级和原 `onCheck` 回调。完成状态仍是现有 `ItemState.status` 的 `done/todo`，沿用 `setItemStatus` 与已有 IndexedDB/同步流程，没有新增存储字段、schema 或导入逻辑。

## 手机版行为

- 日程卡片隐藏复选框；导航按钮保留 `aria-label="导航"`，仅显示图标，触控区为 44px；标题、副标题、备注完整换行。
- 长按 2 秒显示底部进度条，然后切换完成状态，支持设备振动 30ms；已完成卡片突出背景/边框、标题删除线。完成项仍按原逻辑下沉。
- 移动超过 10px、滚动、pointercancel/touchcancel、失焦、窗口尺寸变化均取消计时；导航按钮和箭头不启动计时。取消或完成后拦截本次松手产生的点击，避免误开详情。
- 卡片禁用文字选择和系统长按菜单。保留点击查看详情；键盘 Enter 查看、Space 切换完成状态。
- 日程页隐藏城市大面板、原倒计时和工具导航，保留粘性日期条。倒计时移到旅游概览。
- 底部为「导入 / 筹备 / 日程 / 概览 / 设置」，日程按钮突出且直接跳转。其他分组始终只有两个圆形子入口；超过两个功能的分组通过第二个入口的面板承载。
- 分组点击空白、重复点击、选择子项或 Escape 收起；只展开一个；按当前页面高亮父按钮；适配底部 safe area 和减少动态效果设置。

## 此前完整 review 发现的待修事项

以下为另外的功能/数据问题，不包含在本次两项手机版 UI 修改中：

1. 删除某旅程的共享文件可能连带删除另一旅程仍引用的云端文件。
2. 重命名后重新导入时，证明资料的绑定更新仅比较数组长度，可能漏存同长度但 key 已变的绑定。
3. 文件 hash 缓存仅依赖大小与类型，同大小同类型的新内容可能复用旧 hash。
4. 主用户调整行程顺序后，顺序未完整同步到同伴。
5. 调整旅程开始日期后，保存的原始 Markdown 日期仍旧，后续再编辑/导入可能回退日期。
6. 导入差异比较遗漏仅地址变化，预览可能显示没有修改。
7. JSON 的 `days: [null]` 缺少输入校验，会抛异常。
8. 邀请接受流程存在并发竞争风险（SQL 静态检查，未对线上并发执行验证）。
