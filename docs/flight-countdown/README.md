# 行程页顶部航班卡

仅开发用户授权的航班卡模块。卡片位于行程页原 HeroCover 位置，StoryPage 与 main 一致。默认国旗或用户自己的左右照片，各占卡片宽度 60%，中间 20% 交叉融合。背景固定为黑白 Overlay、opacity 1、contrast 1.2，无模糊和可调滤镜。Pin 内彩色小国旗保留，Pin 图标为 55.2px。

## 界面与行为

- 每阶段仅显示一张卡。原卡片下的日期、离线提示、保存说明、来源和预览入口全部收进右上角设置，不再占据行程页空间。
- 设置中可独立上传、替换左右照片，或恢复该侧当前国家的国旗；切换国家保留自选照片。上传会使用现有图片压缩流程，校验实际可解码性，拦截损坏文件和超过限制的照片。
- 起飞按每航段的当地时区输入，保存 UTC 毫秒及 IANA 时区。去程到点后沿航线飞行 4.6 秒，再切换距离回程起飞的倒数。起飞前的完整飞机已移除导致裁切的父级滤镜。
- 晚进入、刷新或休眠恢复按真实时刻定位；不重播过去起飞。尊重减少动态效果，回程起飞后显示结束。设置中的演示只用组件内存，8.5 秒后恢复真实状态，不写入虚拟时间。

## 数据和改动边界

- 自选照片沿用现有 blobs 表和 useBlobUrl 生命周期，键为 flight-background:<tripId>:origin / destination；没有新表、字段、数据库版本或依赖。
- repo.ts 新增模块专用照片保存函数。删除旅程时清理该旅程的两张照片；含附件旅行包导出仅额外收集该旅程已存在的照片。本机全部备份原有流程自动包含它们。重新导入不删除这些 blob。
- 原有 flightCountdown 是 Trip 的可选配置；导入时保留该值，不改原行程日期、项目、订单或文件绑定。
- ItineraryPage 仅替换原封面接入。PhaseCard 仅隐藏重复倒数，保留准备提醒、统计及原有操作。其他业务流程、主题 tokens、PWA 配置、解析器、依赖和 guard 没有修改。

## 验证

- npm run build 通过。npm test：20 文件 / 184 测试通过，航班模块 12 项，覆盖 UTC、DST、阶段、隔离保存及照片替换、恢复、旅行包往返、重新导入和删除清理。
- qa/flight-countdown/visual.py、interaction.py、motion.py、photos.py 为隔离合成数据验证。开发地址默认 :4190，可用 FLIGHT_QA_URL 覆盖。
- photos.py 在 FLIGHT_QA_PRODUCTION=1 时通过原生 IndexedDB 准备数据，并检查断网刷新和离线上传。FLIGHT_QA_BROWSERS 可选 chromium 或 webkit，默认两者。WebKit 使用独立的普通持久配置（验证工具 Playwright 1.64）；私密会话无法存储 Blob，失败时界面提供使用普通窗口的提示。
- 浏览器覆盖 1280 / 768 / 390 / 320，四季主题、文件错误拦截、照片重载、单侧恢复、国家切换及动画。图片和结果位于本目录。
