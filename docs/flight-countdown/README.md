# 行程页顶部航班卡

仅开发用户授权的航班卡模块。卡片位于行程页原 HeroCover 位置，StoryPage 与 main 一致。默认国旗或用户自己的左右照片，各占卡片宽度 60%，中间 20% 交叉融合。卡片使用当前四季主题的深色色板（color-leather-dark），白色系文字；背景固定为黑白 Overlay、opacity 1、contrast 1.2，无模糊和可调滤镜。Pin 内彩色小国旗保留，Pin 图标为 55.2px。

## 界面与行为

- 标题层级依次为 H1 旅程名称、H2「启程倒计时」（返程阶段为「返程倒计时」）、H3 去程及回程的起飞日期时间；两段各标注该时刻的准确 UTC 偏移。
- 标准高度手机 232.5px / 平板电脑 172.5px，相比原 310px / 230px 缩短 25%；超长标题和放大字体可撑开以保留信息。
- 桌面原顶部旅程标题和设置移入左面板，手机保留紧凑的设置栏。Screen / TabBar 仅新增可选 sidebarHeader 插槽，只有 ItineraryPage 使用，其他页面原 header 和导航默认行为不变。

- 每阶段仅显示一张卡。原卡片下的日期、离线提示、保存说明、来源和预览入口全部收进右上角设置，不再占据行程页空间。
- 设置中可独立上传、替换左右照片，或恢复该侧当前国家的国旗；切换国家保留自选照片。上传会使用现有图片压缩流程，校验实际可解码性，拦截损坏文件和超过限制的照片。
- 起飞按每航段的当地时区输入，保存 UTC 毫秒及 IANA 时区。去程到点后沿航线飞行 4.6 秒，再切换距离回程起飞的倒数。起飞前的完整飞机已移除导致裁切的父级滤镜。
- 晚进入、刷新或休眠恢复按真实时刻定位；不重播过去起飞。尊重减少动态效果，回程起飞后显示结束。设置中的演示只用组件内存，8.5 秒后恢复真实状态，不写入虚拟时间。

## 数据和改动边界

- 自选照片沿用现有 blobs 表和 useBlobUrl 生命周期，键为 flight-background:<tripId>:origin / destination；没有新表、字段、数据库版本或依赖。
- repo.ts 新增模块专用照片保存函数。删除旅程时清理该旅程的两张照片；含附件旅行包导出仅额外收集该旅程已存在的照片。本机全部备份原有流程自动包含它们。重新导入不删除这些 blob。
- 原有 flightCountdown 是 Trip 的可选配置；导入时保留该值，不改原行程日期、项目、订单或文件绑定。
- ItineraryPage 仅替换原封面接入。PhaseCard 仅隐藏重复倒数，保留准备提醒、统计及原有操作。其他业务流程、主题 tokens、PWA 配置、解析器、依赖和 guard 没有修改。

## 验证

- npm run build 通过。npm test：21 文件 / 197 测试通过，航班配置及照片模块 12 项、PDF 解析 13 项，覆盖 UTC、DST、阶段、隔离保存及照片替换、恢复、旅行包往返、重新导入和删除清理。
- qa/flight-countdown/visual.py、interaction.py、motion.py、photos.py 为隔离合成数据验证。开发地址默认 :4190，可用 FLIGHT_QA_URL 覆盖。
- photos.py 在 FLIGHT_QA_PRODUCTION=1 时通过原生 IndexedDB 准备数据，并检查断网刷新和离线上传。FLIGHT_QA_BROWSERS 可选 chromium 或 webkit，默认两者。WebKit 使用独立的普通持久配置（验证工具 Playwright 1.64）；私密会话无法存储 Blob，失败时界面提供使用普通窗口的提示。
- 浏览器覆盖 1280 / 768 / 390 / 320，四季主题、文件错误拦截、照片重载、单侧恢复、国家切换及动画。图片和结果位于本目录。

## 文字型 PDF 机票识别

航班卡设置中新增「从 PDF 机票填写时间」，主卡片及已确认的视觉不变。

- 选择本机 PDF（最多 4 份）后自动读取候选，也可读取本旅程资料中已保存、未加密的 PDF 机票。既有资料上传、查看及保存流程没有修改；本入口选择的文件仅用于本次识别，不会自动新增附件。
- 用户为去程和回程选择起飞候选，日期自动填入原表单；核对国家及时区后使用原「保存航班时间」确认。读取、选择及出错都不修改保存值。同一航段不能同时作为去程和回程。
- 不自动猜测机场时区。PDF 填入的当地时间在修改对应国家时保持不变；保存后才按确认的 IANA 时区转换 UTC。原有手动输入/已保存设置的换国换算规则保留。
- 支持 ISO/中文日期、英文月份、24/12 小时制、两列起飞/抵达版式、跨页及重复旅客。明确抵达、登机、出票和时长时间排除；日/月不明确时保留两个解释供选择。两位年份按旅程年份推定并明确标注待核对。无法识别的版式可继续手动填写，不保证覆盖所有航空公司模板。
- 只读文字，不含 OCR。扫描/无文字、加密、损坏或无法找到时间时提供反馈；保留手动填写。每份限制 20 MB / 20 页 / 200,000 字符，30 秒超时；关闭面板会取消并释放 PDF worker。
- 复用现有 pdfjs-dist 包及本地 worker，没有新依赖、API、服务器、数据库字段或资料写入。仅新增模块独立读取器、纯解析器、设置入口及专用测试。
- `flightTicket.test.ts` 新增 13 项语义测试，完整测试为 21 文件 / 197 项通过。`qa/flight-countdown/ticket.py` 使用合成机票验证读取、航段选择、保存前无写入、美国设备时区下 UTC 保存、换国保持票面时间、已存资料只读、扫描件/密码提示、歧义日期与离线识别。`make_ticket_fixtures.py` 可用 ReportLab 重建已附的合成 PDF；不含真实旅客数据。
- 本机 dev 测试设 `FLIGHT_QA_URL`；正式构建与在线预览另设 `FLIGHT_QA_PRODUCTION=1`，`FLIGHT_QA_BROWSERS=chromium` 或 `webkit`（WebKit 需要普通持久配置）。
- 正式构建 Chromium / Safari WebKit 在 1280 / 768 / 390 下均通过；美国设备时区下核对 UTC 保存、关闭重开、读取已存附件和断网刷新后识别通过。结果见 `ticket-checks-*.json`，截图为 `ticket-*-*.png`。

护栏例外还包括新纯解析器、专用 PDF 读取器和测试；保持检查与锁文件原样，交由维护者审核，不合并生产。
